# F6 · Фича: внесение времён кругов маршалом

> **Тип:** фича (доменная) · **Слой:** backend (конфиг + storage + handler + тесты) · **Сложность:** средняя · **Статус:** 🚧 бэкенд готов, экран маршала — следующий шаг

## Цель

Замкнуть цикл рекордов. До этой задачи времена кругов попадали в систему только
через seed-файл: таблица рекордов (F4) и паспорт трассы (F5) показывали данные,
которые никак не могли появиться в работающем сервисе. Теперь маршал вносит
результаты прошедшего заезда, и они сразу отражаются в рекордах.

Полный путь: заезд состоялся → маршал вносит времена → таблица рекордов
обновилась → гонщик видит свой результат.

## Решение по модели доступа

Ролей в системе нет: авторизация одна, по телефону клиента. Вводить полноценные
роли ради одной операции — несоразмерно: это таблицы прав, выдача ролей и экраны
управления ими.

Взята модель, которая соответствует реальности картодрома: **у маршала свой
планшет, настроенный один раз**. Технически — общий секрет в переменной окружения
`MARSHAL_TOKEN` и заголовок `X-Marshal-Token` в запросе.

**Пустой `MARSHAL_TOKEN` выключает функцию целиком** — маршрут не регистрируется
вовсе, а не отвечает отказом. Это защита от недосмотра: оставить открытую запись
в чужие результаты, забыв что-то настроить, невозможно — включение требует
осознанного действия.

Токен сравнивается за постоянное время (`crypto/subtle`). Обычное сравнение строк
завершается на первом несовпавшем байте, и по времени ответа секрет подбирается
посимвольно.

## Реализация

`POST /bookings/{bookingID}/lap-results`

```json
{ "lap_times_ms": [44120, 42318, 42990] }
```

```json
{ "booking_id": "…", "racer_name": "Ольга", "route_name": "Городское кольцо",
  "laps": 3, "best_lap_ms": 40850, "is_track_record": true }
```

1. `internal/config` — `MarshalToken` с безопасным умолчанием (пусто = выключено).
2. `internal/storage/postgres/slots.go` — `BookingForLapEntry` (бронь + контекст для
   проверок) и `ReplaceLapResults` (замена результатов в транзакции, возвращает
   прежний лучший круг трассы — по нему считается, побит ли рекорд).
3. `internal/http/handlers/lapresults.go` — `MarshalHandler`. Отдельный обработчик,
   а не часть `SlotHandler`: у него своя модель доступа.
4. `internal/http/router.go` + `cmd/api/main.go` — регистрация только при заданном токене.

## Правила, зафиксированные тестами

Все проверки вращаются вокруг одного риска: **испорченная таблица рекордов**.
Опечатка или запись не в ту бронь остаются в системе навсегда.

| Правило | Почему |
|---|---|
| Повторная отправка **заменяет** круги, а не добавляет | Маршал исправляет опечатку. При добавлении повторная отправка удвоила бы круги и оставила ошибочное время в рекордах |
| Круг быстрее 5 сек или медленнее 10 мин отклоняется | Почти наверняка опечатка (секунды вместо миллисекунд, лишний ноль). Один неверный ноль навсегда сделает «рекордсменом» того, кто им не был |
| Для будущего заезда результаты не принимаются | Заезд, который не состоялся, не мог дать кругов. Без проверки опечатка в выборе брони наградила бы рекордом участника будущей гонки |
| Для отменённой записи результаты не принимаются | Гонщик не выходил на трассу |
| Без токена и с чужим токеном — 403 | |
| Без `MARSHAL_TOKEN` маршрута не существует | Отдельный тест: защита от того, чтобы забыть выключить функцию |

## Что попутно исправлено в демо-данных

Живой прогон вскрыл нестыковку: **времена кругов были привязаны к заездам, которые
ещё не состоялись**. Данные противоречили сами себе, а маршалу нечего было вносить —
все демо-заезды лежали в будущем.

Сид перестроен: два заезда стали прошедшими (им и принадлежат рекорды), добавлены
два предстоящих для записи.

Заодно даты переведены на **относительные** (`now() - interval '12 days'` вместо
констант). Сид применяется при каждом старте сервиса, поэтому демо-данные больше
не устаревают — раньше здесь стояли фиксированные даты, и через пару месяцев все
«предстоящие» заезды оказались в прошлом.

Отдельно проверено, что кириллический токен не работает: значения заголовков HTTP
ограничены ASCII. Токен должен быть латиницей.
