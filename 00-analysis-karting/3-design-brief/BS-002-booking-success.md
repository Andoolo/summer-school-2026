# BS-002 · Подтверждение записи («Вы записаны»)

> Полноэкранное подтверждение успешной брони. По дизайну — **экран**, не Bottom Sheet (RR-D03);
> ID `BS-002` сохранён, чтобы не ломать ссылки.

**Зона:** АЗ · **Приоритет:** High · **Тип:** Экран · **Связанные требования:** FR-30, FR-33 / UC-1, US-5, US-12 / NFR-17

## Назначение

Подтвердить успешную бронь, показать сводку, напомнить об офлайн-оплате и предложить дальнейшие
шаги. Точка запроса разрешения на push (после первой записи).

## Навигация

- **Входящая:** после успешного `createBooking` на SCR-004.
- **Исходящая:** «Мои бронирования» (primary) → SCR-005; «Готово» (secondary) → SCR-002.

## Элементы экрана

| Элемент | Назначение |
| :-- | :-- |
| Иллюстрация/иконка успеха | Положительное подтверждение |
| Заголовок «Вы записаны!» | Статус брони |
| Сводка записи | Слот (дата/время, конфигурация), число мест, экипировка, `price_total` |
| Блок «Оплата на месте» | «Наличные или перевод» — напоминание об офлайн-оплате |
| Кнопка «Мои бронирования» (primary) | Переход в список броней |
| Кнопка «Готово» (secondary) | Возврат к списку слотов |

## Поведение и валидации

- **Свободного закрытия нет** (свайпом/бэкдропом): уход только по двум кнопкам (RR-D03).
- **Запрос push-разрешения (LOGIC-007):** после **первой** успешной записи — системный диалог
  разрешения на уведомления. При отказе — приложение работает штатно без push (FR-33).
- **`reminder_hours`** клиент берёт из ответа `createBooking` (24ч и 2ч), не хардкодит (NFR-17).

## Состояния

| Состояние | Поведение |
| :-- | :-- |
| Первая запись | Запрос push-разрешения |
| Повторная запись | Без запроса push (уже получено/отклонено) |

## Применяемые логики

- [LOGIC-007] Запрос push-разрешения.

## Требования

FR-30, FR-33 / UC-1, US-5, US-12 / NFR-17.
