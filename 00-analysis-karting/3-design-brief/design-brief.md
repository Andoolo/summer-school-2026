## Цель и контекст

**«Апекс»** заменяет ручную запись на заезды через Telegram и доску маркером, устраняя двойные
брони на карт и путаницу с местами. Клиент самостоятельно просматривает слоты, фильтрует,
записывается (себя и гостей), выбирает вариант экипировки, отменяет записи и получает напоминания.
Платформа — **нативное/гибридное мобильное приложение для iOS и Android** (mobile-first для
использования у трассы), распространяется через App Store и Google Play (R-002). Веб-версии нет.

**Скоуп — только роль «Клиент».** Маршал и владелец работают через существующую инфраструктуру/
админку и в приложение не входят. Справочные данные — read-only из API; оплата — офлайн (наличные
/ перевод), приложение лишь показывает цену и фиксирует запись.

**Что входит в MVP (принятые решения):**
- **Профиль клиента (R-009):** просмотр и редактирование имени и телефона, выход из аккаунта,
  удаление аккаунта — экран [SCR-007](SCR-007-profile.md).
- **Цена и прокат экипировки (R-010):** прокат экипировки — **отдельный тариф**; итог записи =
  `цена за место-карт × число мест + тариф проката × число прокатных комплектов`. **Своя
  экипировка — бесплатно.** **Карт всегда центра.** Валюта — **рубли (RUB)**. Итоговую цену
  считает и возвращает сервер; приложение показывает её, не пересчитывая.
- **Место сбора и трасса (R-011):** обязательное место сбора + карта с геометрией трассы на
  [SCR-003](SCR-003-slot-card.md)/[SCR-006](SCR-006-booking-details.md); при недоступности карты —
  текстовый fallback (см. [00-foundations §8](00-foundations.md#8-карта-трассы-статичный-превью-яндекскарты)).
- **Отмена (R-014):** только **целиком** (нельзя отменить часть мест из записи).

Подробнее о продукте, аудитории, дизайн-принципах и контексте использования —
[00-foundations.md §1–2](00-foundations.md#1-продукт-и-аудитория).

## Роли и их задачи

| Роль | Что делает в приложении |
| :-- | :-- |
| **Клиент** | Просматривает и фильтрует слоты, записывается (себя + гости), выбирает вариант экипировки, смотрит цену, отменяет записи, видит свои брони, получает напоминания. |
| Маршал / Владелец | **Не входят в приложение** — работают через существующую инфраструктуру/админку (вне скоупа). |

## Сквозные правила (foundations)

Единые для всех экранов требования вынесены в **[00-foundations.md](00-foundations.md)**:
дизайн-принципы, структурные токены (контраст, тач-зоны, иерархия — без бренда), каркас и
навигация (таб-бар, bottom sheet, нижний CTA), сквозной паттерн состояний (Loading / Content /
Empty / Error), tone of voice и общая микрокопия, доступность, напоминания, безопасность данных,
карта трассы, глоссарий.

> **Объём визуальных требований.** Документы задают **функционально-структурные** требования
> (иерархия, компоненты, поведение, ограничения), без прескриптивных цветов/шрифтов — бренд в
> исходной аналитике не зафиксирован; визуальный язык определяет дизайнер.

## Пользовательские сценарии (user flows)

- **Вход (трёхшаговый):** запуск → SCR-001 (телефон → код из SMS → имя для нового) → SCR-002.
- **Запись (UC-1):** SCR-002 → SCR-003 → SCR-004 → BS-002 → (SCR-005). ≤ 3 экранов до подтверждения
  (NFR-2). После **первой** записи в BS-002 запрашивается разрешение на push.
- **Фильтрация (UC-3):** SCR-002 → BS-001 → SCR-002 (с применёнными фильтрами; множественный выбор
  типа конфигурации/маршала).
- **Отмена (UC-2):** SCR-005 → SCR-006 → BS-003 → SCR-006 (с обновлённым статусом). Отмена — только
  целиком.
- **Профиль:** SCR-007 — просмотр/редактирование имени и телефона, выход, удаление аккаунта,
  справочные пункты; выход/удаление → SCR-001.
- **Карта трассы:** SCR-003 / SCR-006 → BS-004 (интерактивная карта с трассой) → возврат.

> **Карта трассы и место сбора.** На [SCR-003](SCR-003-slot-card.md) и
> [SCR-006](SCR-006-booking-details.md) трасса показывается **картой Яндекс (статичный превью с
> выделенной линией трассы)**, а **место сбора** — обязательный элемент (пин на карте + текстовый
> адрес). Тап по карте открывает шторку [BS-004 «Карта трассы»](BS-004-route-map.md) с открытой
> интерактивной картой и отрисованной трассой. Правила —
> [00-foundations.md §8](00-foundations.md#8-карта-трассы-статичный-превью-яндекскарты).

## Состояния экранов

Единый паттерн для всех экранов с запросами — Loading (скелетон/шиммер) → Content → Empty (заглушка
+ подсказка) → Error (+ «Обновить»). Описан один раз в
[00-foundations.md §5](00-foundations.md#5-сквозной-паттерн-состояний-экрана); специфичные состояния
(disabled CTA «Записаться» при 0 мест, бейдж «Поздняя отмена» и т.п.) — в соответствующих экранных
документах.

## Тон, бренд, ограничения

- **Тон:** простой, прямой, дружелюбный, без давления и штрафов; обращение на «вы» —
  [00-foundations.md §6](00-foundations.md#6-tone-of-voice-и-общая-микрокопия).
- **Бренд:** не зафиксирован в аналитике — визуальный язык за дизайнером; обязательны лишь
  структурные ограничения (контраст, размеры, иерархия) — [§3](00-foundations.md#3-структурные-токены-без-бренда).
- **Доступность / mobile-first:** крупные тач-зоны, высокий контраст, читаемость на солнце и в
  рукавах/перчатках — [§3, §7](00-foundations.md#7-доступность-nfr-1-nfr-25).
- **Что НЕ делаем на старте (Phase 2+):** онлайн-оплата, рейтинг маршала, авто-отмена по погоде,
  программа лояльности, публичные отзывы, интерфейсы маршала/владельца, подбор карта под рост —
  см. [feature-list §7](../5-mobile-app-spec/feature-list.md).
