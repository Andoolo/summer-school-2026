## 1. Продукт и аудитория

**«Апекс»** — клиентское мобильное приложение картинг-центра: самостоятельная запись на групповые
заезды, замена ручной записи через Telegram/доску маркером. Устраняет двойные брони на карт и
путаницу с местами. Платформа — **нативное/гибридное приложение для iOS и Android** (mobile-first
для использования у трассы), распространяется через App Store и Google Play (R-002). Веб-версии
нет.

**Скоуп — только роль «Клиент».** Маршал и владелец работают через существующую инфраструктуру и
в приложение не входят. Справочные данные — read-only из API; оплата — офлайн (наличные /
перевод), приложение лишь показывает цену и фиксирует запись.

**Аудитория.** Клиенты центра — любители прогулочного/любительского картинга. Разный возраст и
цифровая грамотность. Сезонная нагрузка, пик — выходные.

**Контекст использования (важно для дизайна):**
- У трассы, часто **на открытом воздухе, на ярком солнце** → критичны контраст и читаемость.
- Возможны **рукава куртки / перчатки** при записи → крупные тач-зоны, минимум точных жестов.
- **Нестабильная связь** у трассы → offline-просмотр кэша, понятные ошибки сети, retry.
- Записываются **себя и гостей** (+1–2) → быстрый сценарий записи, ≤3 экранов до подтверждения.

## 2. Дизайн-принципы

1. **Скорость записи важнее полноты.** Главный сценарий — записаться за минимум шагов (NFR-2,
   ≤3 экрана). Лишние поля/шаги — вон.
2. **Крупно и контрастно.** Читаемость на солнце и в рукавицах: высокий контраст, крупные тач-зоны
   (≥44pt), размеренный шрифт (NFR-1, NFR-25).
3. **Сервер — истина, клиент — зеркало.** Цена, число мест, статус отмены приходят из API; клиент
   не пересчитывает и не додумывает (FR-45, R-021). Честное отображение реального состояния.
4. **Без шоков и штрафов.** Tone of voice — дружелюбный, без давления. Поздняя отмена — без
   обвинений и денег, только фиксация (FR-18).
5. **Понятные пустоты и ошибки.** Любой empty/error-случай сопровождается подсказкой, что делать
   дальше (см. §5).
6. **Числа не хардкодятся.** Потолки конфигураций, прокатный фонд, цены, лимиты — из данных
   слота/конфигурации (R-003, FR-13/FR-14).

## 3. Структурные токены (без бренда)

> Бренд в аналитике не зафиксирован — конкретные цвета/шрифты за дизайнером. Здесь — только
> **структурные ограничения**, обязательные для любых макетов (соответствие NFR-1, NFR-25).

| Токен | Правило | Обоснование |
| :-- | :-- | :-- |
| Минимальный touch-target | **≥ 44pt** для всех интерактивных элементов | NFR-25; контекст у трассы (рукава/перчатки) |
| Контраст текста | соответствие **WCAG 2.1 уровень AA** | NFR-25; чтение на солнце |
| Динамический шрифт | поддержка системного увеличения (**Dynamic Type / шкала шрифта**) без потери функциональности | NFR-25 |
| Смысл ≠ только цвет | статус/доступность мест передаются **не одним цветом** (иконка/текст/бейдж) | NFR-25 |
| Минимальные размеры экранов | работоспособность и читаемость на малых экранах | NFR-25 |
| Иерархия | один primary-элемент на экран (главное действие), второстепенное — secondary/ghost | NFR-2; принцип 1 |

## 4. Каркас и навигация

### 4.1 Зоны приложения
- **НЗ — неавторизованная зона:** экран входа (SCR-001).
- **АЗ — авторизованная зона:** таб-бар с тремя разделами — **«Заезды»** (SCR-002), **«Мои
  бронирования»** (SCR-005), **«Профиль»** (SCR-007).

### 4.2 Таб-бар (АЗ)
| Пункт | Экран | Когда активен |
| :-- | :-- | :-- |
| Заезды | SCR-002 Список слотов | всегда в АЗ (дом) |
| Мои бронирования | SCR-005 Мои записи | всегда в АЗ |
| Профиль | SCR-007 Профиль | всегда в АЗ |

> Таб-бар показывается на всех экранах АЗ, кроме полноэкранных модальных: BS-002 «Вы записаны» и
> интерактивной карты BS-004 (на них — собственные заголовки/закрытие).

### 4.3 Bottom Sheet
Временные шторки снизу для вспомогательных действий: фильтры (BS-001), подтверждение записи
(BS-002 — по дизайну полноэкранный успех, RR-D03), подтверждение отмены (BS-003), карта (BS-004).
Закрытие — по кнопке/бэкдропу, кроме BS-002 (уход только по двум кнопкам).

### 4.4 Нижний CTA
Главное действие экрана — закреплено внизу (sticky primary button), всегда в зоне большого пальца:
«Получить код», «Записаться», «Отменить запись». Состояние disabled — пока валидация не пройдена
или мест нет.

## 5. Сквозной паттерн состояний экрана

Единый для всех экранов с сетевыми запросами ([SCR-002](SCR-002-slot-list.md),
[SCR-003](SCR-003-slot-card.md), [SCR-005](SCR-005-my-bookings.md), [SCR-006](SCR-006-booking-details.md)):

```
Loading  →  Content  →  Empty  →  Error
(скелетон/    (данные)   (заглушка    (+ «Обновить»,
 шиммер)                  + подсказка)  единый retry)
```

| Состояние | Правило |
| :-- | :-- |
| **Loading** | Скелетон/шиммер по форме контента; не блокирует таб-бар |
| **Content** | Основные данные экрана |
| **Empty** | Заглушка + подсказка, **что сделать** (напр. «Заездов пока нет — загляните позже», «У вас нет броней — выберите заезд») |
| **Error** | Единый Error/Retry: причина + кнопка «Повторить»; для брони — повтор по тому же `Idempotency-Key` (R-022, NFR-24) |

> **Offline (NFR-24).** Просмотр из кэша с пометкой **«данные могли устареть»**; мутации (бронь,
> отмена) офлайн недоступны — понятное сообщение, CTA disabled. Таймаут запроса ~10 с.

## 6. Tone of voice и общая микрокопия

- **Обращение на «ты» или «вы»** — единообразно по приложению (рекомендация: на «вы», нейтрально).
- **Прямо и дружелюбно**, без жаргона и запугивания. Никаких «ошибка!» заглавными.
- **Правило 2 часов** — поясняется человеческим текстом (канон, используется дословно во всех
  экранах): «Можно отменить бесплатно за 2 часа до старта. Позже ваше место в заезде за вами
  сохранится, но карт простаивает.»
- **Цена** — «Оплата на месте: наличные или перевод», без имитации онлайн-оплаты.
- **Локализация ошибок** — по коду из [матрице ошибок](../2-requirements/error-matrix.md).
- **Бейджи слотов различаются** (важно): «Мест нет» — только для заполненных (`free_seats=0`);
  «Заезд отменён центром» — для отменённых центром слотов (это разные ситуации, их нельзя путать).

| Ситуация | Эталонная фраза |
| :-- | :-- |
| Заполненный слот (`free_seats=0`) | «Свободных мест нет» (бейдж) + CTA «Записаться» disabled |
| Слот отменён центром | «Заезд отменён центром» + причина (из push) |
| Поздняя отмена | «Поздняя отмена: ваше место в заезде сохранено. Штраф не взимается.» |
| Нет сети (просмотр) | «Нет связи. Показываем сохранённые данные — они могли устареть.» |
| Нет сети (запись) | «Чтобы записаться, нужно подключение к интернету.» |
| Успешная бронь | «Вы записаны!» + сводка + «Оплата на месте» |

## 7. Доступность (NFR-1, NFR-25)

Приёмочные критерии a11y (проверяются при приёмке):
- Контраст текста/ключевых элементов — **WCAG 2.1 AA**.
- Минимальный touch-target **≥ 44pt**.
- Поддержка системного увеличения шрифта (**Dynamic Type / шкала шрифта**) без потери функций.
- Все интерактивные элементы и изображения имеют **labels для screen reader** (VoiceOver/TalkBack).
- Смысл (статус, ошибки, доступность мест) **не передаётся одним цветом** — дублируется
  иконкой/текстом/бейджем.
- Интерфейс работоспособен и читаем на **малых экранах**.

## 8. Карта трассы (статичный превью, Яндекс.Карты)

> [RR-D07] Геометрия конфигурации трассы и место сбора — обязательные элементы карточки слота.

- На [SCR-003](SCR-003-slot-card.md) и [SCR-006](SCR-006-booking-details.md) трасса показывается
  **статичным превью Яндекс.Карт** с выделенной линией трассы (`geometry`); **место сбора** —
  обязательный элемент (пин + текстовый адрес `meeting_point`).
- Тап по карте открывает шторку [BS-004 «Карта трассы»](BS-004-route-map.md) — интерактивная карта
  с отрисованной трассой и пином места сбора.
- **Ключ Яндекс.Карт — параметр конфигурации окружения**, не в коде/модели/репозитории (NFR-26).
- **Fallback** при недоступности карт/квоты: адрес/координаты текстом, без интерактивной карты;
  бронирование продолжает работать (NFR-23, FR-44).

## 9. Безопасность данных

- **Сессия** — JWT access/refresh; токены только в защищённом хранилище (Keychain/Keystore), не в
  логах/незащищённом storage (NFR-18).
- **401-flow:** при 401 клиент пытается refresh; при неуспехе — очистка токенов + экран входа.
- **ПДн (имя, телефон):** маскирование номера в UI (`+7 *** *** ** 67`); запрет логирования полного
  номера и OTP; передача только по TLS (NFR-20).
- **Удаление аккаунта:** активные брони аннулируются, прошедшие — анонимизируются (R-009, FR-48).

## 10. Напоминания (push, MVP)

- Канал MVP — **системный push** (APNs/FCM), нативное приложение (R-006, NFR-17).
- **Тайминг:** за **24 ч и за 2 ч** до старта (`reminder_hours = [24, 2]`, согласовано с
  заказчиком 2026-06-30). Конкретные часы — из ответа `createBooking`, не хардкодить.
- **Запрос разрешения** — после **первой** успешной записи (BS-002), не на онбординге.
- **При отказе** в уведомлениях приложение работает штатно: напоминания не доставляются, брони
  доступны в «Мои бронирования»; возможна подсказка включить уведомления (FR-33).
- Также push используется для **отмены заезда центром** (FR-46): бронь → «Отменён центром» + причина.
- SMS/email/inbox — **Phase 2**.

## 11. Глоссарий UI

Термины домена — в [описании домена](../1-elicitation/domain-description.md). UI-термины (CTA,
empty state, fallback, offline-режим) — там же, в разделе «Технические термины».

> **Ключевое правило для дизайнера (картинг).** **Карт всегда выдаётся центром** — варианта
> «свой карт» нет; одно место = один карт. Выбор «своя / прокатная» относится **только к
> экипировке** (шлем + подшлемник), а не к карте. «Слот» = «заезд» = временной слот группового
> заезда (синонимы).
