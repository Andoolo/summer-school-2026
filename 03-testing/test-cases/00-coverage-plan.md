# Столп 2 · План-таблица покрытия тест-кейсами

> Планирование «сверху вниз» (по методологии лекции): сначала карта покрытия по экранам/потокам,
> затем детализация ядра. Детальные кейсы — в [`core-flows.md`](core-flows.md) (Markdown) и
> [`test-cases.yaml`](test-cases.yaml) (машиночитаемо, под TMS/автоматизацию).
>
> **Приоритеты:** P0 — критичный путь/деньги/безопасность; P1 — важное; P2 — доп./edge.
> **Тип:** C — компонентный (фича), S — сценарный (регресс).
> **Регресс Блока 2** отмечен фичей (B1/B2/B3/F1/F2/F3).

## Матрица негативов (API, из UC-1 R-023)

| Код | HTTP | Где тестируется |
|-----|------|-----------------|
| bad_request | 400 | валидация телефона/имени/seats/rental |
| unauthorized | 401 | protected-эндпоинты без/с истёкшим токеном → refresh → logout (**F3**) |
| forbidden | 403 | чужая бронь (NFR-12) |
| not_found | 404 | несуществующий slot/booking |
| conflict | 409 | double_booking, already_cancelled, idempotency_key_conflict |
| gone | 410 | slot_cancelled *(H6 — нет в контракте cancelBooking)* |
| unprocessable | 422 | slot_started (запись/отмена после старта) |
| too_many_requests | 429 | OTP resend/attempts *(на read — H8, пробел)* |
| slot_full | 409 | нет мест / нехватка проката *(различение — H9, пробел)* |

## Известные блокеры оракула (из Столпа 1)

Кейсы, зависящие от нерешённых требований, помечены в детализации тегом `@needs-clarification`:
- окно слотов по умолчанию (C1: FR-9 vs US-2);
- порядок при пагинации броней (C2 — на сервере закрыт **B2**, спека расходится);
- различение 409 «нет мест» vs «нет проката» (H9);
- 410 в отмене (H6); реакция на 429 при чтении (H8); logout при 5xx (H11).
